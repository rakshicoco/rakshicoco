# ============================================================

# Audit all:
#
# src/app/**

# src/lib/**

# Search specifically for:
#
# - sequential Supabase queries that can be parallelized

# - repeated queries for the same data
# - unnecessary router.refresh()
# - unnecessary revalidation

#
# ============================================================
# PHASE 3 — FIX DATABASE ROUND TRIPS
# ============================================================
#
# Optimize Supabase access WITHOUT changing business logic.
#
# Rules:
#
# 1. Never use select('*') unless genuinely required.
#
# 2. Replace with explicit columns.
#
# Example:
#
# BAD:
# .select('*')
#
# GOOD:
# .select('id,name,phone,location,active')
#
# 3. Parallelize independent queries.
#
# BAD:
#
# const farms = await ...
# const buyers = await ...
# const stats = await ...
#
# GOOD:
#
# const [farms, buyers, stats] = await Promise.all([
#   ...,
#   ...,
#   ...
# ])
#
# 4. Never issue the same query multiple times during one page load
# unless the data genuinely changed.
#
# 5. Add pagination to large lists.
#
# Default mobile page size:
# 20–30 records.
#
# 6. Add appropriate database indexes only where query analysis
# demonstrates they are useful.
#
# Do NOT create random indexes.
#
# Inspect existing Supabase/PostgreSQL schema and migrations first.
#
# ============================================================
# PHASE 4 — FIX NEXT.JS NAVIGATION
# ============================================================
#
# Audit App Router navigation.
#
# Goal:
# Clicking Dashboard / Operations / Sales / Finance / More must
# transition quickly without unnecessary full application reloads.
#
# Use Next.js client navigation where appropriate.
#
# Do NOT convert the entire application into a client-side SPA.
#
# Preserve:
# - authentication
# - Server Components where useful
# - Server Actions
# - RLS
# - Supabase security
# - existing production behavior
#
# Remove unnecessary:
# - router.refresh()
# - duplicate server requests
# - redundant revalidation
#
# where they are not required for correctness.
#
# ============================================================
# PHASE 5 — OPTIMIZE SERVER ACTIONS
# ============================================================
#
# Audit every important mutation:
#
# Farm
# Purchase
# Cutting
# Grouping
# Transport
# Processing
# Sales Order
# Dispatch
# Billing
# Payment
# Expenses
#
# For each action:
#
# 1. Validate input once.
# 2. Authenticate once.
# 3. Authorize once.
# 4. Execute only required DB operations.
# 5. Avoid unnecessary read-after-write queries.
# 6. Return the minimum data required by the UI.
#
# If a mutation currently performs:
#
# INSERT
# -> SELECT
# -> SELECT
# -> SELECT
# -> router.refresh()
#
# determine whether it can safely become:
#
# INSERT
# -> return required result
# -> targeted UI update
#
# NEVER remove a query that is required for financial,
# inventory, audit, or security correctness.
#
